Устройство предназначено для управления **дискретными выходами (DO)** удалённого Modbus-устройства по протоколу **Modbus RTU**.

- Фактическое состояние катушек опрашивается функцией **READ_COILS (0x01)**.
- Запись маски выходов выполняется функцией **WRITE_MULTIPLE_COILS (0x0F)**.

Поддерживает до **64 портов**, автоматически создаёт соответствующее количество входных (`do1..doN`) и выходных (`di1..diN`) портов.

- Выходы `di1..diN` выдают **фактическое** состояние катушек `0` или `1` — обратная связь от устройства.
- Входы `do1..doN` принимают **желаемое** состояние: `0` или `1` (любое ненулевое значение считается `1`).
- Нумерация соответствует Modbus: **бит 0 первого байта → `do1`/`di1`**, **бит 1 → `do2`/`di2`**, и т.д.

## Логика работы

1. При поступлении на вход `bus` провайдера от `vrack2-net.ConverterBus` выполняется Modbus-запрос `0x01` с количеством битов = `countDO`.
2. Полученный байт состояния обновляет `shares.bitmask` (фактическую маску) и разбирается побитно начиная с младшего бита (`bit 0`). Значения обновляются в `shares.do` и передаются в выходные порты **только при изменении**, если не включён режим `eachGate`.
3. При приходе значения на вход `doN` обновляется **желаемая** маска `shares.write` (сравнение идёт с ней, а не с фактическим состоянием). Если желание изменилось — устройство ставит себя в срочную очередь провайдера (`addUrgentQueue`), чтобы не ждать следующего цикла опроса.
4. После опроса состояния, если `shares.write` отличается от `shares.bitmask`, отправляется запрос `0x0F` с полной маской `shares.write` (биты упакованы от младшего к старшему).
5. Запись повторяется каждый цикл, пока фактическая маска, прочитанная на следующем опросе, не совпадёт с желаемой. Поэтому запись доживает до подтверждения даже если устройство не приняло маску с первого раза.

## Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `address` | `1` | Modbus-адрес устройства |
| `countDO` | `8` | Количество DO-портов (1..64) |
| `eachGate` | `false` | `true` — пуш в выходы при каждом опросе, `false` — только при изменении |
| `timeout` | `700` | Таймаут Modbus-запроса, мс |
| `offTimeout` | `30000` | Таймаут неприхода провайдера, после которого устройство считается offline |

## Shares

| Ключ | Описание |
|---|---|
| `online` | Устройство доступно (последний цикл опроса прошёл успешно) |
| `do[N-1]` | Фактическое состояние выхода N (0/1) |
| `bitmask[]` | Фактическая маска состояния, побайтно |
| `write[]` | Желаемая маска, побайтно |

## Замечания

- Последний байт при `countDO` не кратном 8 маскируется по количеству значимых битов — лишние биты ответа не попадают в сравнение масок и не вызывают лишних записей.
- Устройства с адресом `0` (широковещательные) не должны получать ответов — для них этот мастер не подходит.
- Если ведомый отвечает исключением (`func | 0x80`), `ModbusRTU.parseResponse` бросает `V2MODBUS_EXCEPTION` (с кодом и адресом), цикл `update` падает и устройство уходит в `offline`.
